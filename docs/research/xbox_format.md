# Xbox / Microsoft Store Game Format

## Purpose
Document the Xbox Game Pass (formerly Microsoft Store) game installation format for detection, metadata extraction, and migration scoping.

## Overview

Xbox / Microsoft Store games (also called "Xbox Game Pass" or "Play Anywhere" titles) are distributed through the Microsoft Store and managed by the Xbox app / Game Services. These games use a packaging system fundamentally different from traditional installers — they use AppX/MSIX packages with complex permission models, making detection and especially migration significantly harder than other launchers.

## Detection Markers

### Primary Signal: `default-metadata.json`

A `default-metadata.json` file at the game folder root identifies an Xbox/Microsoft Store-managed game. This file is generated by the Xbox Game Pass integration layer and contains package metadata.

### Secondary Markers (for confirmation)
- `appxmanifest.xml` — AppX package manifest (may be present in package root)
- `resources.pri` — Windows resource index file
- `.cat` files — Security catalog files (code signing)

### False Positive Avoidance
`default-metadata.json` is specific to Xbox Game Pass titles. False positives are unlikely. The C# implementation should verify the file contains recognizable Xbox/GamePass fields before treating it as a confirmed detection.

## Install Locations

### Game Install Root (WindowsApps)
All Microsoft Store apps (including games) are installed under the **highly restricted** `WindowsApps` folder:

```
C:\Program Files\WindowsApps\
```

This folder is:
- **Hidden by default** — requires `Show hidden files` + `Hide protected operating system files`
- **Permission-restricted** — even Administrators cannot browse it without `takeown` / `icacls` modifications
- **Managed entirely by the Store installer** — manual changes break the package signature

Each game is installed in a subfolder named after its **PackageFullName**:
```
C:\Program Files\WindowsApps\<PackageFullName>_<version>_<architecture>__<publisherid>\
```

### Alternative: Xbox Gaming Root (Xbox App-managed)
The Xbox app may also install to a user-configurable directory:
```
%USERPROFILE%\XboxGames\
```
or by default:
```
%LOCALAPPDATA%\Packages\Microsoft.GamingApp_<publisherid>\LocalCache\XboxGames\
```

### Registry / Package Manager

The authoritative source for installed packages is **not registry** — it's the Windows Package Manager API:

```
powershell Get-AppxPackage | Where-Object { $_.SignatureKind -eq 'Store' }
```

Key fields:
- `PackageFullName` — unique identifier (used as install folder name)
- `PackageFamilyName` — family identifier (used for activation)
- `InstallLocation` — the `WindowsApps` subfolder
- `IsDevelopmentMode` — must be `false` for properly installed games

## Game Folder Structure

```
<PackageFullName>/
├── default-metadata.json         # Detection marker
├── appxmanifest.xml              # Package manifest (XML)
├── resources.pri                 # Resource index
├── <GameExecutable>.exe          # Main executable (or .exe inside subfolder)
├── <Game>.exe                    # May be renamed to package name
├── Assets/                       # Tile images, logos
├── VCLibs/                       # VC++ runtime dependency
└── ...                           # Game engine files
```

### Important: Executable Discovery

Unlike traditional installs, the main `.exe` may not be at the package root. It may be nested inside a subfolder matching the developer's original directory layout. The `appxmanifest.xml` contains `<Application>` entries with `Executable` attributes pointing to the actual launch targets.

## Launch Patterns

Xbox games can be launched via:
1. **Shell URI:** `shell:appsFolder\<PackageFamilyName>!<AppId>` — the primary launch mechanism
2. **GameBar / Xbox Game Bar:** The "Play" button in the Xbox app uses the shell URI
3. **Direct executable:** `<GameExecutable>.exe` — works for some titles but may bypass Game Services (achievements, cloud saves may not work)
4. **gamelaunchhelper.exe:** Some titles use a launcher helper process

The C# implementation should use method (1) — the shell App URI — as the default launch target for full Xbox integration.

## Migration Considerations

### ⚠️ EXTREMELY LIMITED

Xbox / Microsoft Store games are **the most difficult to migrate** of all supported launchers. Key constraints:

1. **WindowsApps is protected** — `takeown` + `icacls` required to even read the folder
2. **Package signing** — every file is signed; moving files breaks the signature and the game will not launch
3. **No manifest file** — unlike Steam (ACF) or Epic (.item), there's no editable manifest that maps install location
4. **Package dependency** — VCLibs, DirectX, and other framework packages are separate Store packages
5. **Windows re-detection** — if the game is removed from WindowsApps, the Store must re-download it

### What's Possible
| Operation | Feasibility | Approach |
|-----------|------------|----------|
| Detection only | ✅ Yes | Detect via `default-metadata.json` + `Get-AppxPackage` |
| Reinstall to new drive | ⚠️ Partial | Use `Move-AppxPackage` PowerShell cmdlet (Store-provided) |
| Manual folder copy | ❌ No | Breaks package signature |
| Symlink/junction | ❌ No | Not supported for AppX packages |
| Manifest repair | ❌ No | No manifest to repair |

### Repair Notes

Xbox / Microsoft Store games have no editable manifest. GamingCommander's role is
**detection-only**:

- Detect the game at its current location via `default-metadata.json`
- If the user has moved Xbox games, they must use the official method:
  - Windows Settings → Apps → Installed Apps → select game → Move
  - Or PowerShell: `Move-AppxPackage`
- GamingCommander will **never** attempt to modify WindowsApps or Xbox game registrations
- The game will be detected as an Xbox title but no repair action will be offered
